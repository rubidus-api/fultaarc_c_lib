0. 블랙박스 오라클 계약 및 출발 사실 (Phase 0)

이 문서에서 타깃 프로그램(RAR.EXE)은 내부 바이너리·메모리·어셈블리를 전혀 열람하지 않는 순수 블랙박스 함수 O(pw, n) -> bytes[n]로 취급한다. 평문 전체가 0x00인 Store-mode(-m0) 아카이브의 암호화된 데이터 영역을 읽으면 곧바로 키스트림을 관측할 수 있다.

1. 파이프라인 개요 & Stage 0 (다항식·가중치·출발 가설 클래스)

탐색 공간은 데이터로 유도된 대수적 불변량과 오너 승인 출발 가설(AMENDMENT-2026-11-16)만으로 닫힌 5-워드 파라미터 패밀리로 축소된다. (정답 상수는 단 1개도 가정하지 않는다.)

  • DATA-DERIVED 선형 CRC-32 구조(Cycle 208): 고정 길이 차분 커널의 F2 역방향 점화식이 33차 다항식 0x30D4326D9 = (x + 1) * 0x104C11DB7을 소거하며, 32차 원시 인자 0x104C11DB7이 출현한다.
  • APPROVED-PRIOR RECALL-208 / RECALL-209: Cycle 208의 0x104C11DB7을 표준 IEEE 802.3 반사 CRC-32 테이블 T_ref(0xEDB88320)로 해석하고, 소형 16비트 워드 상태 기계(물리적 레지스터 주장이 아닌 수학적 모형 클래스)를 탐색 출발점으로 삼는다.
  • DATA-DERIVED Cycle 238/239 가중치 소거 & CRC 최하위 비트 불변성(Cycle 259/265): 경험적 승수 3573의 모듈러 역수 (-3573) * 0x89A3 == 1 (mod 216)을 곱하면 모든 256바이트 가중치가 H = sum_{c in e} ((T_ref[c] >> 16) + c) mod 216로 붕괴한다. 또한 (crc >> 1, bx, acc >> 1)이 첫 512바이트를 결정하며 R & 1(CRC 비트 0)은 출력에 전혀 영향을 주지 않는다.

탐색 모형 패밀리(Parameterized Search Class)

RECALL-208/209 출발 클래스 하에서, 미지 파라미터는 유한 튜플 theta = (hr_rot, add_c, m1_rot, m_rot, t_rot, acc_k2, K2_0, S_0(c))다. 단계 I~IV는 theta 전체(264 이상)를 무작정 탐색하지 않고, 관측 데이터 슬라이스를 직교 분리하여 각 단계가 최대 65,536개 후보 스캔만으로 끝나도록 분해한다.

2. Stage I — 동일 (R, bx) 파이버로 H 회전량(hr_rot) 분리

유효 비밀번호 접두어 e = pw[:77]에서 R = crc32_unfinalized(e)와 b_x = XOR_{c in e} c가 같도록 고른 비밀번호 집합(work/c248/oracle.json: 6,144행, 동일 (R, b_x) 쌍 5,888개)을 잡는다. 같은 파이버 안에서는 W_0, S_0, M_1, K_{2,1}, u_0가 모두 같으므로 out[0]의 차이는 오직 H(덧셈 누산기)에서만 나온다.

out^(a)[0] XOR out^(b)[0] == (ror16(H^(a), hr_rot) >> 8) XOR (ror16(H^(b), hr_rot) >> 8)
  • 16개 회전 후보 hr_rot in 0..15를 전수 대조하면 오직 hr_rot = 2만 0 오차를 내며 차선 후보는 5,857개 쌍에서 즉시 기각된다.
  • 따라서 첫 바이트에서 H의 기여분을 Y_0 = out[0] ^ (ror16(H, 2) >> 8)로 정확히 벗겨 낼 수 있다.
# Stage I minimal reproducible recipe (requires only c248 constant-(R, bx) anchor pairs)
survivors = []
for hr_rot in range(16):
    err = 0
    for row_a, row_b in same_R_bx_pairs:
        pred_diff = ((ror16(H(row_a), hr_rot) >> 8) ^ (ror16(H(row_b), hr_rot) >> 8))
        if (row_a.out[0] ^ row_b.out[0]) != pred_diff:
            err += 1
    if err == 0:
        survivors.append(hr_rot)
# Result on c248 (5,888 pairs): survivors == [2], min_other_err == 5,857

3. Stage II — F2 좌영공간 비트 필링(c239 Byte 0)

이제 b_x = 0x4c로 고정된 비밀번호 2,095행(work/c239/oracle.json)을 사용해 미지의 상수 s_0 = S_0(0x4c)와 덧셈 상수 add_c를 복원한다. R_LO = R & 0xFFFF, R_HI = (R >> 16) & 0xFFFF, u_0 = ((R_LO + add_c) >> 1) & 0xFF라 하자. H가 제거된 Y_0의 비트 b in 0..7 (16비트 위치 k = 8 + b)은 다음 항등식을 만족한다.

((Y_0 >> b) & 1) XOR (((R_LO + add_c) >> k) & 1) XOR (((s_0 + T_HI[u_0]) >> k) & 1) == (K_{2,1} >> k) & 1 in span_F2(1, R_HI[0..15], T_LO[u_0][0..15]) [33 columns]
  1. b = 0 (비트 8) 전수 스캔: 250행 위에서 33열 디자인 행렬 X(u_0) = [1 | R_HI | T_LO[u_0]]의 F2 좌영공간 기저 K(차원 >= 217, 우연 일치 확률 ~ 2-217)를 구한다. 인덱스 u_0는 add_c mod 512에만 의존하므로 (add_lo9 even, s0_lo8) 256 * 256 = 65,536쌍만 검사하면 된다. 결과는 392개 생존자 (add_lo9 in ['0x134', '0x1b4', '0x34', '0xb4']).
  2. 순차 비트 필링 (k = 9..15): 살아남은 392개에서 비트 9부터 비트 15까지 올라가며 add_c의 상위 비트와 s_0의 비트를 하나씩 확장·소거하면 add_c mod 215 = 0x1234가 유일 확정되며, s_0(0x4c) mod 215는 정확히 33개 밴드 [0x7200 .. 0x7220]로 좁혀진다.
  3. 33개 밴드가 생기는 대수적 이유: IEEE 802.3 테이블에서 max_u (T_HI[u] & 0xFF) == 0xDF이므로 s0_lo8 in [0x00 .. 0x20] 범위에서는 (T_HI[u] & 0xFF) + s0_lo8 <= 0xDF + 0x20 = 0xFF < 256가 되어 어떤 u_0에서도 비트 7 -> 비트 8 캐리가 0이 된다. 따라서 바이트 0 단독으로는 s0_lo8 33개 값을 구분할 수 없고, 바이트 1(Stage III)이 필요하다.
  4. K2,1 회전 파라미터 복원: Z_0 = Y_0 ^ ((R_LO + 0x1234) >> 8) ^ ((s_0 + T_HI[u_0]) >> 8)을 2,095행 전체에서 검증하면 stage2_z0_gf2_err == 0이며, 16 x 16 회전 쌍 (m1_rot, t_rot) 중 오직 (m1_rot = 1, t_rot = 1, const_hi = 0x7f)만 유일 생존한다.

# Step A (k=8): scan (add_lo9 in range(0, 512, 2)) x (s0_lo8 in range(256)) = 65,536 pairs
#   reject whenever (left_nullspace(X(u0)) @ rhs_bit8) % 2 != 0  -> 392 survivors
# Step B (k=9..15): lift add_c bits 9..14 and s0 bits 8..14 one bit per round using rhs_bit(k)
#   -> unique add_c mod 2^15 = 0x1234, s0 mod 2^15 in [0x7200 .. 0x7220] (33 candidates)
# Step C: check Z0 == ((ror16(rol16(R_HI, m1_rot) ^ ror16(T_LO[u0], t_rot) ^ K2_0)) >> 8)
#   across all 16x16 (m1_rot, t_rot) -> unique (m1_rot=1, t_rot=1, K2_0_hi=0x7F)

4. Stage III — Byte 1 필링 & 블랙박스 Z24 게이지 불변성 정리

4.1 Byte 1(out[1])에서 s0_lo8 및 스텝 회전 유일 확정

두 번째 스텝(i = 1)의 입력 워드 W_1의 상위 바이트는 이미 관측값 out[0] 그 자체다! W_1의 하위 바이트만 R_LO, u_0, s0_lo8, k2_lo8로 표현되므로, u_1 = ((W_1 + add_c) >> 1) & 0xFF 역시 미지수 s0_lo8 in [0x00..0x20](33개)과 짝수 k2_lo8 in 0..254(128개) 총 4,224개 쌍만 스캔하면 결정된다.

  • 70행 위 49열 디자인 행렬 span_F2(1, R_HI, T_LO[u_0], T_LO[u_1])에서 Y_1의 하위 2비트를 검사하면 오직 s0_lo8 = 0x08 + 짝지어진 k2_lo8 in {0xFE, 0xFF}만 통과한다.
  • 이제 남은 미지수는 비트 15·비트 0 모호성 23 = 8가지, acc_k2 in {False, True}(누적 XOR K2 ^= M vs 비누적), 스텝 회전 16 x 16 = 256가지, 총 4,096개 튜플뿐이다. 2,095행 x 16바이트 전체를 검증하면 acc_k2 = True, m_rot = 2, t_rot = 1이 유일 확정되며, 정확히 8개 원소 궤도만 0오차로 살아남는다.

4.2 블랙박스 Z24 게이지 등가성 정리 & 패리티 붕괴 보조정리

Theorem (Exact Black-Box Z24 Gauge Equivalence): add_c가 짝수일 때, (r, a, b, d) in {0,1}4에 대해 아래 16개 파라미터화는 모든 가능한 비밀번호 pw와 출력 길이 n에서 비트 단위로 완전히 동일한 키스트림을 생성한다.
(R ^ r, 0x1234 ^ (a << 15), S_0(c) ^ (b << 15), 0x7FFE ^ ((a ^ b) << 15) ^ d)
  • LSB 분리 (r, d): add_c가 짝수이므로 덧셈 W + add_c는 비트 0에서 비트 1로 캐리를 생성하지 않는다. 따라서 R[0](r) 또는 K2_0[0](d)가 뒤집히면 매 스텝 W의 최하위 비트 0만 반전될 뿐, u_i = ((W + add_c) >> 1) & 0xFF와 출력 W >> 8에는 영구히 영향이 0이다.
  • MSB 무캐리 (a, b): 16비트 모듈러 덧셈에서 최상위 비트 15(0x8000)는 더 높은 비트로 캐리 아웃이 없고 (W + add_c) >> 1 시프트로 빠져나가며 K2, S와의 XOR에만 선형 참여한다. 따라서 add_c의 MSB(a) 또는 S_0의 MSB(b)를 뒤집을 때 K2_0의 MSB를 a ^ b로 보상하면 모든 스텝의 W' ^ S ^ Hr ^ K2가 항등적으로 보존된다.
  • 따름정리 (Parity-Collapse Lemma): 만약 실제 생성기의 add_c가 홀수(add_c & 1 == 1)라면 W[0] = 1일 때 비트 0에서 비트 1로 캐리가 발생하여 r, d가 u_i와 즉시 결합한다. 그 결과 8-원소 궤도가 정확히 4개(MSB-only Z22)로 붕괴한다! (이는 7절의 Planted Odd 0x5A7D 대조군으로 실증되었다.)

5. Stage IV — 전 128 bx 구간 S_0(bx) & uint8_t 부호 규명

표준 게이지 대표원((a=0, b=1, d=1) -> add_c = 0x1234, S_0(0x4c) = 0xF208, K2_0 = 0xFFFF)을 고정한 뒤, 128개 b_x in 0..127 구간별로 나뉜 데이터셋(work/c247/oracle.json, 구간당 32행)에서 16비트 s_0 in 0..65535를 전수 스캔한다.

  • 128 / 128 전 구간 유일 해: 단 하나의 b_x에서도 동률(tie)이 발생하지 않으며(stage4_non_unique_bins = []), 복원된 128개 값은 stage4_gf2_err_128 = 0(완전 아핀 F2 함수)이며, 기저 7벡터(0x3097, 0x612e, 0xc41d, 0x883a, 0x1074, 0x20e8, 0x41d0) 및 영점 S_0(0) = 0xFFFF가 S_0(b_x) == 0xFFFF ^ (T_ref[b_x] & 0xFFFF) ^ b_x와 128/128 정확히 일치한다.
  • 0x80..0xFF 원시 바이트(k109) 4-원소 분리 검증: 아카이브 코퍼스 0007-k109_pw.json.gz(400행)에서 H·S_0 계산 시 바이트 c를 무부호(uint8_t, 0..255)로 다루는지 부호(int8_t, -128..127)로 다루는지, 그리고 S_0(c)에 T_LO[c]의 비트 7 이상(c >= 128)이 들어가는지를 2x2 교차 검사한다.

6. 최종 알고리즘 명세, C99 참조 구현 및 검산 추적표

6.1 표준 C99 구현 (tools/libcleanroom/src/rar15_cipher.c 원문)

전역 가변 상태와 외부 심볼 참조(nm -u rar15_cipher.o = 0) 없이 스택 지역 CRC-32 테이블로 완전 스레드 안전하게 구현된 코드다.

/* rar15_cipher.c - RAR 1.5 stream cipher: block XOR + keystream generator.
 *
 * Implements rar15_decrypt_block and rar15_keystream in standalone clean-room C99 from
 * mathematics alone using the IEEE 802.3 CRC-32 polynomial (0xEDB88320, generated from its
 * definition on the stack for full reentrancy with zero global state or external libc calls)
 * and the Cycle 323/324 verified key-schedule and 5-word (<=54-bit initial) 16-bit recurrence --
 * zero runtime oracle calls, zero stored keystreams, zero external/third-party archiver source.
 *
 * Provenance (Amendment 2026-11-16, Cycles 323-324):
 *   APPROVED-PRIOR : RECALL-208 (small 16-bit word state hypothesis class, non-physical),
 *                    RECALL-209 (IEEE 802.3 CRC-32 polynomial 0xEDB88320 candidate structure).
 *   DATA-DERIVED   : 77-byte prefix truncation, unsigned byte promotion, R/H/S accumulators,
 *                    5x16-bit live loop state (w, m, k2, hr, s_state), +0x1234 step,
 *                    ror16(_,2)/ror16(_,1), K2^=M, W>>8; unique up to Cycle 324 Z_2^3/Z_2^4
 *                    black-box gauge equivalence.
 *
 * SPDX-License-Identifier: MIT
 */
#include "rar15.h"

static void build_crc32_table(uint32_t tbl[256]) {
    for (uint32_t i = 0; i < 256u; i++) {
        uint32_t c = i;
        for (int k = 0; k < 8; k++)
            c = (c & 1u) ? (0xEDB88320u ^ (c >> 1)) : (c >> 1);
        tbl[i] = c;
    }
}

static uint16_t rol16(uint16_t x, unsigned r) {
    r &= 15u;
    if (!r) return x;
    return (uint16_t)((((uint32_t)x << r) | ((uint32_t)x >> (16u - r))) & 0xFFFFu);
}

static uint16_t ror16(uint16_t x, unsigned r) {
    r &= 15u;
    if (!r) return x;
    return (uint16_t)((((uint32_t)x >> r) | ((uint32_t)x << (16u - r))) & 0xFFFFu);
}

int rar15_decrypt_block(uint8_t *data, size_t data_len, const uint8_t *ks, size_t ks_len) {
    if (!data || !ks) return RAR15_ERR_PARAM;
    if (ks_len < data_len) return RAR15_ERR_BUFFER;
    for (size_t i = 0; i < data_len; i++)
        data[i] ^= ks[i];
    return RAR15_OK;
}

size_t rar15_keystream(const char *password, uint8_t *out, size_t max_out) {
    if (!password || !out || max_out == 0)
        return 0;

    uint32_t crc_tbl[256];
    build_crc32_table(crc_tbl);

    size_t plen = 0;
    while (plen < 77u && password[plen] != '\0')
        plen++;

    const uint8_t *pw = (const uint8_t *)password;
    uint32_t r_state = 0xFFFFFFFFu;
    uint16_t h_state = 0u;
    uint16_t s_state = 0xFFFFu;
    for (size_t i = 0; i < plen; i++) {
        uint8_t c = pw[i];
        r_state = (r_state >> 8) ^ crc_tbl[(r_state ^ c) & 0xFFu];
        h_state = (uint16_t)(h_state + (uint16_t)(crc_tbl[c] >> 16) + (uint16_t)c);
        s_state ^= (uint16_t)((crc_tbl[c] & 0xFFFFu) ^ (uint16_t)c);
    }

    uint16_t w = (uint16_t)(r_state & 0xFFFFu);
    uint16_t m = rol16((uint16_t)((r_state >> 16) & 0xFFFFu), 1u);
    uint16_t k2 = 0xFFFFu;
    uint16_t hr = h_state;

    for (size_t i = 0; i < max_out; i++) {
        w = (uint16_t)(w + 0x1234u);
        uint32_t t = crc_tbl[(w >> 1) & 0xFFu];
        s_state = (uint16_t)(s_state + (uint16_t)(t >> 16));
        m = (uint16_t)(ror16(m, 2u) ^ ror16((uint16_t)(t & 0xFFFFu), 1u));
        k2 ^= m;
        hr = ror16(hr, 2u);
        w ^= (uint16_t)(s_state ^ hr ^ k2);
        out[i] = (uint8_t)(w >> 8);
    }
    return max_out;
}

8. 사람 또는 AI를 위한 독립 재유도 실행 청사진 (Executable Blueprint)

다른 AI 에이전트나 분석가가 블랙박스 오라클(또는 본 패키지의 03-reproducible-evidence/work/ 데이터)만을 손에 쥐고 Stage 0부터 최종 C 코드까지 동일하게 재유도하기 위한 절차 규격이다.

DERIVATION_BLUEPRINT RAR15_KEYSTREAM_CLEANROOM:
  INPUT  : Black-box oracle O(pw_bytes, n) -> bytes[n] (or equivalent pre-collected corpora)
  PRIORS : APPROVED-PRIOR RECALL-208 (small 16-bit word-state class)
           APPROVED-PRIOR RECALL-209 (standard IEEE 802.3 T_ref, poly = 0xEDB88320, after observing 0x104C11DB7 in Stage 0)

  STEP 0 [Oracle Probing & Linear Invariant Extraction]:
    - Collect same-prefix (len 77..85), single-byte raw (0x01..0xFF), and store-mode archives.
    - Establish cutoff = 77, R = unfinalized_crc32(pw[:77]), bit-0 dead invariance (R & 1 unused),
      and algebraic weight collapse H(pw[:77]) = sum((T_ref[c] >> 16) + c) mod 2^16.
    - Partition probe sets:
        D_fibre (same (R, bx), varying H), e.g. c248 (6,144 rows -> 5,888 same-(R,bx) pairs)
        D_bx0   (fixed bx = XOR(pw) == 0x4c, varying R), e.g. c239 (2,095 rows, >= 16 bytes)
        D_bxall (all 128 ASCII bx values), e.g. c247 (4,096 rows = 128 x 32)
        D_raw   (raw bytes including 0x80..0xFF), e.g. k109 (400 rows)

  STEP 1 [Stage I: Isolate H rotation hr_rot on D_fibre]:
    - Scan r in 0..15; require out_a[0] ^ out_b[0] == (ror16(H_a, r)>>8) ^ (ror16(H_b, r)>>8) for ALL pairs.
    - Stop iff unique survivor hr_rot emerges (observed: hr_rot = 2, 0 err vs 5,857).
    - Compute residual Y_0 = out[0] ^ (ror16(H, hr_rot) >> 8) on D_bx0.

  STEP 2 [Stage II: GF(2) Left-Nullspace Bit-Peeling on D_bx0 Byte 0]:
    - Fix N >= 250 rows. Build 33-col GF(2) matrix X(u0) = [1 | bits(R_HI) | bits(T_LO[u0])], compute left nullspace K.
    - Scan 65,536 pairs (add_lo9 even in 0..511, s0_lo8 in 0..255) checking (K @ rhs_bit8(add_lo9, s0_lo8)) % 2 == 0.
    - Peel k = 9..15 upward bit-by-bit using K @ rhs_bit(k) == 0 to pin add_c mod 2^15 and narrow s0(bx0) mod 2^15.
    - Verify Z0 residuals and scan 16x16 (m1_rot, t_rot) over GF(2) span X(u0) to uniquely fix (m1_rot, t_rot, const_hi).

  STEP 3 [Stage III: Byte 1 Peeling & Z_2^4 Orbit Determination on D_bx0]:
    - Substitute W1_hi = out[0]; solve u1 = ((W1 + add_c) >> 1) & 0xFF over surviving s0_lo8 band x even k2_lo8 (0..254).
    - Use 49-col GF(2) span [1 | R_HI | T_LO[u0] | T_LO[u1]] on Y_1[0..1] to pin (s0_lo8, k2_lo8 & 0xFE).
    - Scan 2^3 (add_b15, s0_b15, k2_b0) x 2 (acc_k2) x 16^2 (m_rot, t_rot) = 4,096 tuples on 16+ stream bytes.
    - Output: unique (m_rot, t_rot, acc_k2=True) and exact equivalence orbit O (size 8 if add_c even, else 4).

  STEP 4 [Stage IV: Full Cross-bx Table S_0(c) & Signedness Resolution]:
    - Pick any gauge representative in O (e.g., canonical (add_c=0x1234, s0_0x4c=0xF208, K2_0=0xFFFF)).
    - For each bx in 0..127 of D_bxall, scan s0 in 0..65535 on byte 0..15 -> expect 128/128 unique survivors.
    - Check GF(2) linearity of S_0(bx) and match against 0xFFFF ^ T_LO[bx] ^ bx.
    - Test D_raw (c >= 0x80) across {uint8, int8} x {bit7 T_LO vs masked} -> expect unique 0-error unsigned match.

  STEP 5 [Dual Controls & Independent Blind Verification Gate]:
    - Run SAME solver pipeline on synthetic Planted-Even, Planted-Odd (verifying Z_2^2 parity collapse), and 4 negatives.
    - Collect strictly fresh CSPRNG blind holdouts disjoint from all training/enum corpora; require 0 byte errors.
    - Implement standalone C99 function + unit tests; verify 0 external symbols (nm -u) and full decryption gate.
