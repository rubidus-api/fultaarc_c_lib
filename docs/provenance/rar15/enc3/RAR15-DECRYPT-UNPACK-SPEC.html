1. End-to-End Encrypted Extraction Pipeline

Encrypted RAR 1.5 entries follow a Compress-then-Encrypt design: each independent file entry compresses plaintext first and XORs the resulting PACK_SIZE stream with a password keystream. Extraction therefore always proceeds in 5 strict stages: Container Parse -> Security Gate -> Keystream XOR Decryption -> Decompression -> Plaintext CRC-32 Verification.

For the clean-room black-box algebraic derivation of the keystream generator (rar15_keystream) itself, see RAR15-DERIVATION-GUIDE.html (and the Markdown counterpart of this specification in RAR15-DECRYPT-UNPACK-SPEC.md).

2. Container Parsing, Bounds Guards & Security Controls (rar15_container.c, rarextract.c)

All multi-byte integer fields are little-endian. Generic blocks follow immediately after the 7-byte signature Rar!\x1a\x07\x00 (hex 52 61 72 21 1a 07 00).

3. Stream Cipher Decryption (rar15_cipher.c)

When flags & 0x0004 is set, the PACK_SIZE payload starting at block + head_size is XORed with rar15_keystream(pw, ks, PACK_SIZE). Each non-solid file entry resets the keystream generator at byte index 0.

1. Effective prefix e = pw[:77] (unsigned uint8_t c in 0..255), T_ref = IEEE 802.3 CRC-32 table (0xEDB88320, built on stack) 2. Key schedule: R = unfinalized_crc32(e), H = sum((T_ref[c] >> 16) + c) mod 2^16, S_0 = 0xFFFF ^ XOR((T_ref[c] & 0xFFFF) ^ c) 3. Init state: W = R & 0xFFFF, M = rol16((R >> 16) & 0xFFFF, 1), K2 = 0xFFFF, Hr = H, S = S_0 4. Step i = 0..PACK_SIZE-1: W = (W + 0x1234) & 0xFFFF; t = T_ref[(W >> 1) & 0xFF] S = (S + (t >> 16)) & 0xFFFF M = ror16(M, 2) ^ ror16(t & 0xFFFF, 1) K2 ^= M; Hr = ror16(Hr, 2); W ^= (S ^ Hr ^ K2) packed[i] ^= (W >> 8) & 0xFF

4. Decompression Algorithms (rar15_unpack.c & u15_unpack.{h,c})

rar15_unpack(method, in, in_len, out, out_len) reconstructs exact plaintext of size UNP_SIZE. Method 0x30 is raw Store passthrough; all five compressed methods 0x31..0x35 share a single decoder (u15_unpack) because encoder presets -m1..-m5 vary compression search effort rather than bitstream grammar.

5. CRC-32 Integrity Check & Error Contract (rar15_crc32.c, rar15.h)

Even after u15_unpack returns U15_OK with produced == UNP_SIZE, output is only written to disk when the IEEE 802.3 CRC-32 (0xEDB88320) of the reconstructed plaintext matches FILE_CRC bit-for-bit.

Status CodeValueCondition
RAR15_OK0Container parse, decryption, decompression, CRC-32 match, and write succeeded
RAR15_ERR_PARAM-1NULL pointer, unsafe archive output path (Zip-Slip), or write I/O error
RAR15_ERR_FORMAT-2Bad magic/header, head_size < 11/32, wraparound overflow, truncated or unobserved Huffman code
RAR15_ERR_UNSUPPORTED-3Unsupported flags (SPLIT/SOLID/LARGE/DIR) or METHOD outside 0x30..0x35
RAR15_ERR_CRC-5Reconstructed plaintext CRC-32 does not equal FILE_CRC (fail closed on wrong password)
RAR15_ERR_BUFFER-6Insufficient keystream buffer or allocation failure
